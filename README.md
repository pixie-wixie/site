## Про проєкт

**Піксі Віксі (Pixie Wixie)** — незалежний українськомовний інформаційний блог про OnlyFans і світ авторського контенту. Проєкт допомагає читачам орієнтуватися в цифровому середовищі, оцінювати власні можливості та приймати усвідомлені рішення.

Тут говоримо про підготовку до авторської роботи, приватність, взаємодію з аудиторією й особисті межі. Пишемо спокійно та по суті, без стереотипів і обіцянок легкого заробітку.

## Що є на сайті

| Розділ | Зміст |
| --- | --- |
| **Головна** | Знайомство з блогом, його матеріалами, місією та принципами. |
| **Матеріали** | Пронумеровані статті з описом, датою публікації та приблизним часом читання. |
| **Про нас** | Редакційний підхід, незалежність, прозорість і застереження. |

Темна сливова палітра, рожево-бузкові акценти та тематичні ілюстрації об’єднують сторінки в один стиль. Макети адаптовані для телефонів, а основні тексти мають збільшений розмір і комфортні міжрядкові відступи.

## Як влаштований сайт

- **HTML і CSS** — готові статичні сторінки без бекенда, бази даних і JavaScript.
- **GitHub Pages** — публікація файлів із гілки `main`, папки `/(root)`.
- **Python 3** — допоміжні скрипти для створення каталогу та перевірки SEO перед публікацією. На хостингу Python не потрібен.
- **Локальні зображення** — ілюстрації зберігаються в `img/`.
- **Manrope** — шрифт із Google Fonts; за відсутності інтернету використовується системний шрифт.

Для перегляду не потрібні npm, встановлення залежностей або збірка застосунку.

## Структура проєкту

```text
site/
├── index.html                 # Головна
├── materials.html             # Каталог: перші 10 статей
├── about.html                 # Про нас
├── articles/                  # Окремі HTML-файли статей
├── img/                       # Логотип та ілюстрації
├── style.css                  # Спільне оформлення всіх сторінок
├── scripts/
│   ├── build_materials.py      # Каталог і поділ по 10 статей
│   ├── set_site_url.py         # Canonical, метадані й sitemap
│   └── check_seo.py            # Локальна перевірка SEO
├── robots.txt
├── sitemap.xml
├── .nojekyll                   # Публікація без обробки Jekyll
└── README.md
```

Коли статей стане більше десяти, генератор створить `materials-2.html`, `materials-3.html` тощо. Нумерація статей продовжується між сторінками.

## Локальний перегляд

Відкрийте `index.html` у браузері. Навігація працює і при відкритті файлів без сервера.

Або запустіть у папці проєкту:

```bash
python3 -m http.server 8000
```

Після цього відкрийте [localhost:8000](http://localhost:8000).

## Додавання статті

1. Створіть HTML-файл у `articles/`, використовуючи наявну статтю як основу.
2. Оновіть заголовок, текст, зміст і якорі. Вкажіть порядковий номер у `data-article-order` елемента `<article>`.
3. Задайте унікальні `title`, `description`, Open Graph, Twitter Card і JSON-LD типу `BlogPosting`.
4. Вкажіть фактичну дату публікації у видимому `<time>`, полі `datePublished` та метатезі `article:published_time`.
5. Розрахуйте час читання, оновіть видимий підпис і поле `timeRequired`, наприклад `PT7M`.

**Оцінка часу читання:** кількість символів із пробілами в основному тексті, поділена на 1200 й округлена вгору, мінімум одна хвилина. Меню, зміст-посилання, службові підписи та підвал не враховуються. Це редакційна оцінка, а не точний час для кожного читача.

Із папки статті посилайтеся на спільні файли через `../style.css`, `../img/`, `../index.html` і `../materials.html`.

Після редагування виконайте послідовно:

```bash
python3 scripts/build_materials.py
python3 scripts/set_site_url.py https://pixie-wixie.github.io/site/
python3 scripts/check_seo.py
```

Каталог генерується з даних статей. Вносіть зміни до їхніх файлів, оскільки ручні правки карток у `materials.html` будуть перезаписані при генерації. Картки залишаються текстовими, без обкладинок.

## SEO

На сторінках налаштовані:

- унікальні заголовки й метаописи, українська мова та один H1;
- canonical-адреси й метадані для поширення посилань;
- структуровані дані сторінок, статей, каталогу та навігаційного шляху;
- дата публікації, відомості про редакцію й час читання статті;
- sitemap, внутрішні посилання та текстові описи зображень.

Головна доступна за `/site/index.html`, а її canonical — `https://pixie-wixie.github.io/site/`. Посилання навігації містять `index.html`, щоб сайт також працював локально.

`check_seo.py` перевіряє узгодженість метаданих, посилань, заголовків, JSON-LD та sitemap. Він не вимірює швидкість завантаження й не підтверджує індексацію в Google.

Для Google Search Console використовуйте ресурс із префіксом URL `https://pixie-wixie.github.io/site/` та надішліть [sitemap.xml](https://pixie-wixie.github.io/site/sitemap.xml).

> На GitHub Pages файл `/site/robots.txt` не керує скануванням домену: пошуковики шукають його за адресою `/robots.txt`. Для керування цим файлом потрібен доступ до кореня `pixie-wixie.github.io` або власний домен.

## Публікація та оновлення

Репозиторій: [pixie-wixie/site](https://github.com/pixie-wixie/site).

Після генерації та успішної перевірки:

```bash
git status
git add *.html articles/ img/ scripts/ style.css robots.txt sitemap.xml README.md .nojekyll
git add -u
git commit -m "Update site content and SEO metadata"
git push
```

У налаштуваннях GitHub Pages джерело публікації: **Deploy from a branch → main → /(root)**. Зберігайте `.nojekyll` і структуру папок.

Для зміни домену повторно запустіть `scripts/set_site_url.py` з новою публічною HTTPS-адресою, виконайте перевірку й завантажте оновлені файли.
